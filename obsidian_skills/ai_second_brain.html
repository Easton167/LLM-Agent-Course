你到底在造什么

两个工具，两份工作

整套系统的底层只是一堆纯文本文件——这意味着它不绑定任何一家 AI。明年换个模型指过来，它照样能用，因为你拥有的是大脑本身，不是工具。

Obsidian

存储层 · 免费

把所有笔记以纯文本存在你自己的电脑上。笔记之间互相链接，时间久了这些链接会长成一张图谱——一张能看见的「你的想法如何连接」的地图。文件永远属于你。

Claude

大脑层 · （DeepSeek-v4-pro、DeepSeek-v4-flash）

读取整个 vault，把新信息归到该去的位置，和已有的内容建立链接，并基于全部内容回答你的问题。你不用再每次重新自我介绍。

项目结构

每个项目都是一条流水线

四个文件夹，各司其职。想法落在 Inputs，Claude 在 Process 里干活，成品进 Outputs，结果和数据回到 Feedback——反馈再喂回下一轮。

动手环节

9 步完整搭建

每一步都写清楚点哪里、输入什么。没打开过 Claude Code 或 Obsidian 也能跟着做。不需要 MCP：vault 就是普通文件夹，cd 进去再开 claude，它直接读写里面的 Markdown。

  1. 01

    装 Claude Code + CC Switch，接入 DeepSeek

    先装 Claude Code：打开终端，确认 Node.js ≥ 18（node -v），然后跑：

    终端
    npm install -g @anthropic-ai/claude-code

    再装 CC Switch（用来管理 / 切换模型）：打开 cc-switch.cc 或 GitHub Releases，下载对应系统的安装包（Windows .msi / Mac .dmg），安装后打开。

    在 CC Switch 里点 + 添加供应商，选 Anthropic 兼容，填：

    • 名称：DeepSeek
    • Base URL：https://api.deepseek.com/anthropic
    • API Key：到 platform.deepseek.com 申请并粘贴
    • 主模型：deepseek-v4-pro[1m]（复杂任务）；轻量可用 deepseek-v4-flash

    保存后点 启用。Claude Code 支持热切换，一般不用重启终端。开一个空文件夹跑 claude，问一句「你是谁」——能正常回答就说明 DeepSeek 已经接上了。

  2. 02

    装 Obsidian 并建 vault

    到 obsidian.md 下载安装（免费）。欢迎页点 Create new vault，取名比如 brain，选一个文件夹，Create。这个文件夹从现在起就是你的第二大脑。

    先手动建一条笔记感受一下机制：新建笔记，随便写一句话，然后输入 [[goals]]。这个方括号里的词就变成了一个链接。笔记指向笔记，这就是全部核心机制——后面这件事 Claude 会自动帮你做。

  3. 03

    进 vault，打开 Claude Code

    第二大脑就是磁盘上的一堆文本文件。不需要 Local REST API，也不需要给 Claude 单独接线——进目录开会话即可：

    终端
    cd 你的-vault文件夹路径
claude

    测一句：「列出当前目录里的文件」。能列出来就说明它已经站在你的大脑根目录上了。后面几步的 Prompt，都粘贴在这个会话里。

    习惯：Obsidian 负责看图谱和手改笔记；Claude Code 负责读写与整理。两边对着同一个文件夹，关掉 Obsidian 也不影响 Claude 干活。
  4. 04

    把「你自己」装进大脑

    现在 Claude 能读写 vault，但对你一无所知。空的大脑没有用。而且别自己手打——让 Claude 来采访你。在刚才的会话里粘贴：

    Prompt
    你现在要帮我搭建我的第二大脑。请一次只问我一个问题，来建立我的个人档案。需要问到：我是谁、我在做什么；我今年的目标；我希望你用什么方式跟我说话；我的优势和劣势；我当前在做的项目。每问一个问题都要等我回答完，再问下一个。全部问完后，把所有内容写进 vault 根目录下一个叫 CLAUDE.md 的文件，用标题分好层级，这样你每次开新会话都会自动加载它。

    回答的时候，把它当成在给一位新的联合创始人做背景交接。答得越真实，大脑就越懂你。结束后打开 vault 根目录的 CLAUDE.md，你的全部上下文已经落盘——从此不用再自我介绍。

  5. 05

    用正确的结构建项目

    CLAUDE.md 是战略层，项目才是干活的地方。每个项目独立成文件夹，好让 Claude 一次只专注一件事，而不是同时面对你的整个人生。让它自己搭：

    Prompt
    在我的 vault 里创建一个叫 youtube-channel 的项目文件夹。在它里面建四个子文件夹：Inputs、Process、Outputs、Feedback。然后在这个项目文件夹里写一个 CLAUDE.md，说明这个项目是什么、它唯一的目标是什么，以及你在帮我达成这个目标时的具体角色。如果需要更多细节，就来采访我。

    把 youtube-channel 换成你在做的事。内容、财务、客户，每个领域重复一次。

  6. 06

    只打开单个项目来工作

    这是让整套系统保持锋利的关键动作：不要在巨大的总 vault 里干活，只打开当前项目，让 Claude 只看见这一件事。

    Claude Code：退出当前会话，进项目目录再开：

    终端
    cd 你的-vault/youtube-channel
claude

    Obsidian（可选，方便看图谱）：左下角点 vault 名 → Manage vaults → Open folder as a vault → 选同一个项目文件夹 → Trust。

    这时 Claude 只读这个项目的 CLAUDE.md，其余一概忽略。大 vault 用来规划，单个项目用来交付。

  7. 07

    做成 skill，不再重复自己

    skill 就是一个存下来的工作流，喊一声就跑。凡是做过两次以上的事，都该变成一个 skill。在项目会话里粘贴：

    Prompt
    我想把这件事做成一个可复用的 skill。下面是我做 [这个任务] 的方式，附一个例子：[粘贴你的例子或步骤]。把它保存成一个 markdown skill 文件，放在这个项目的 skills 文件夹里，起一个清晰的名字，并写明什么情况下该触发它。

    下次只要说 运行 [名字] 这个 skill，它就按你的方式立刻执行。写客户邮件、备一期视频、给银行流水分类——每个重复任务配一个。

  8. 08

    把「会变的信息」喂进大脑

    静态笔记只是半个大脑。日历、待办、聊天里的承诺，也要落进 vault。原则：把活信息变成文本，让 Claude 去归位。

    做法 A：每天开工前，从飞书 / 钉钉 / 企业微信 / 手机日历里，把今天的日程和待办复制进 vault，例如新建 Inputs/today.md，然后在会话里说：

    Prompt
    读 Inputs/today.md。把今天的日程和待办整理进 tasks 项目：每条写清下一步动作；没有明确下一步的标出来；和已有笔记能链的用 [[链接]] 连上。

    做法 B：从日历 App 导出 .ics 或表格，丢进 Inputs/，让 Claude 解析并归档。

    记住：大脑吃的是文本。信息进了 vault，后面的整理交给 Claude。
  9. 09

    挂上「每日整理」

    把维护做成固定动作，大脑就会自己变整齐。

    方案 A：先把整理流程存成 skill，每天开工进 vault 开 claude，喊一句即可：

    Prompt · 先做成 skill
    把「每日整理」做成 skill：检查 vault，把 Inputs 里的新内容归位并建链接，标记过期笔记，写 3 行昨夜变化总结到 Outputs/daily-summary.md。保存后我只要说「跑每日整理」就执行。

    方案 B：用系统计划任务，到点自动跑一遍。先在 vault 里建 daily.ps1（Windows）：

    daily.ps1
    Set-Location "你的-vault文件夹路径"
claude -p "检查我的 vault。把 Inputs 里的新内容归到正确位置并建立链接；标记过期笔记；把 3 行昨夜变化总结写进 Outputs/daily-summary.md。" --permission-mode acceptEdits

    打开 任务计划程序 → 创建基本任务 → 每天早上 7:00 → 启动程序选 powershell.exe，参数填：

    任务计划程序参数
    -NoProfile -ExecutionPolicy Bypass -File "你的-vault\daily.ps1"

    Mac / Linux 用 cron：cd 你的-vault && claude -p "……" --permission-mode acceptEdits。计划任务跑的时候电脑要醒着。

    选哪个：大多数人用方案 A 就够。想醒来就看到整理结果，再用方案 B。

唯一不能破的规矩

用权限管，不要用提示词管

跟 agent 说「别删这个文件」，那只是建议。只要它技术上能做的事，就假设总有一天它会做。按下面几条落地：

1. 密钥放工具里，不放 vault 里

DeepSeek / 任何 API Key 只写在 CC Switch（或系统环境变量）里。不要写进 CLAUDE.md、Inputs/、聊天记录导出，也不要提交到 Git。vault 是笔记，不是密码本。

2. 干活时只打开该开的目录

用 cd 进当前项目文件夹再开 claude，不要从磁盘根目录或整台电脑的家目录启动。它够得到的文件越少，误伤面越小。敏感材料（证件扫描、银行导出）放在 vault 外面，或单独一个不上 Claude 的文件夹。

3. 用 Claude Code 的权限模式，别关确认

日常交互会话保持默认：改文件、跑命令前它会问你，你点允才执行。会话里可输入 /permissions 查看和收紧规则。

  • 先摸清状况、还不想改文件 → claude --permission-mode plan
  • 定时整理脚本 → 可用 --permission-mode acceptEdits（只自动批文件读写，仍比全开安全）
  • 不要用 --dangerously-skip-permissions / bypassPermissions

4. 接外部服务时给最小权限

以后若接入日历、邮件、公司 API：单独开一把专用 Key，只开只读；不要把「能发信、能删云盘」的主账号 token 交给 agent。能撤销的 Key，比写在 Prompt 里的「请不要发送」管用一万倍。

5. vault 用 Git 兜底

在 vault 根目录 git init，重要节点 commit 一次。Claude 改乱了，可以回滚。这是权限之外的最后一道网。

Keys, not prompts.
控制写在工具配置和权限开关里，不要写在「请你务必……」这种句子里。

结果

同一份工具，完全不同的用法

之前

每次对话都像第一次见面
  • 新开一个窗口，又得把「我是谁、在做什么」说一遍
  • 关掉窗口，上次聊过的细节基本找不回来
  • 笔记、待办、灵感散落在聊天记录和各种 App 里
  • 真正扛上下文的是你自己的脑子，而且老是漏

之后

打开就能接着干
  • 一个 vault 装着你的档案、项目和笔记
  • cd 进去开 claude，它读 CLAUDE.md 就知道你是谁
  • 新信息进 Inputs，整理后链进图谱，越用越密
  • 全是你电脑上的纯文本，换模型也能继续用

你不是在配置一个 Claude，你是在建造自己的记忆。
它每被喂养一天，就聪明一点。

几乎没人真的会去做。大多数人读完这九步，什么都不会建。
今天就开始的那些人，一个月后打开自己的图谱会愣住——因为它记得他们早已忘掉的东西。
