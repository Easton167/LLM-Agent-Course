01

什么是 LangGraph

Definition
LangGraph 是一个用于构建、管理和部署长期运行、具有状态（stateful）的智能体的低阶编排框架与运行时。

关键词 1长期运行 Long-running

跑的不是一次几秒钟的问答，而可能是几分钟、几小时，甚至几天的任务。

关键词 2有状态 Stateful

智能体每走一步，都记得之前发生了什么，数据不会丢。

关键词 3低阶编排 Low-level

不是把一切都封装好的高层框架，而是把流程怎么走、在哪分支、在哪循环的控制权交给你。灵活度高，可控性强。
02

为什么会出现 LangGraph

Why LangGraph

大模型应用从“一问一答”演进到自主规划、调用工具、多步推理的智能体，传统的线性链和简单路由暴露出三个明显的问题。

痛点问题具体表现
01 缺乏循环和状态管理 ReAct 的“思考 → 行动 → 观察”本质上是一个循环：想一下、做一下、看结果，不满意再来一轮。而传统链从头走到尾，很难安全、持久地维护每一轮的执行状态。
02 确定性和灵活性难以平衡 全交给大模型决定下一步 → 黑盒，可能陷入死循环、产生幻觉；全部写死 → 失去智能体的意义。开发者需要的是：该写死的写死，该让模型发挥的让它发挥，两者放在同一套流程里。
03 生产环境需要持久化和人工介入 智能体可能要跑好几个小时，中间服务可能重启；在付款、发邮件、删数据之前，还得停下来等人审批。这要求底层具备原生的持久化和检查点（Checkpointing）能力。
LangGraph 就是为了解决这三个问题而生的。
03

LangGraph 的四大核心能力

Key Capabilities

能力 1细粒度的图结构编排

显式定义节点（Nodes）和边（Edges），搭出包含循环、条件分支、多智能体协同的图结构。流程长什么样，你说了算。

解决痛点 01：缺乏循环

能力 2混合确定性步骤和智能步骤

同一张图里，一个节点是普通业务代码（查数据库、做校验），另一个节点交给大模型做决策。核心流程可控，边缘逻辑灵活。

解决痛点 02：确定性 vs 灵活性

能力 3原生持久化和状态恢复

内置检查点机制，每一步状态自动保存。程序挂了从断点恢复；调试时可回到任意一步查看当时的状态，甚至改了重跑——即“时间旅行”（Time Travel）调试。

解决痛点 01 + 03：状态管理与持久化

能力 4内置人工介入 Human-in-the-loop

图可在任意节点暂停，人来检查、修改状态；审批通过再继续，不通过就回滚。生产环境里非常关键。

解决痛点 03：人工介入

04

关键概念（上）：循环图、节点与边

Cyclical Graphs · Nodes · Edges

① 循环图 Cyclical Graphs

和线性工作流不同，流程允许绕回去、多次交互。工具结果不对？回到“思考”节点再来一次。

多轮迭代、依据动态输入做判断的任务，循环图是刚需。

② 节点 Nodes

工作流里的一个独立单元：可以是一次大模型调用、一个智能体，也可以是一个普通 Python 函数。每个节点负责任务中的一个环节。

③ 边 Edges

定义节点之间怎么连接，决定数据往哪流、流程往哪走。
  • 基础边固定直连：A 做完一定去 B
  • 条件边按规则分流：要调工具去 tools，否则结束
记住一句话：节点负责“做事”，边负责“决定下一步做什么”。
05

关键概念（下）：状态管理与生态集成

State · LangChain · LangSmith

④ 状态管理 State

LangGraph 在所有节点之间维护一个共享的、持久化的状态对象。

  • 每个节点读取 State → 做事 → 更新 State → 交给下一个节点
  • 状态持久化 → 应用可以随时暂停、恢复，不丢失上下文
  • 长周期任务、需要人工介入的场景，都依赖这一点

⑤ 与 LangChain、LangSmith 的集成

LangGraph 不是另起炉灶：它构建在 LangChain 之上，之前学过的模型、提示词、工具、链都能直接放进节点里复用；再配合 LangSmith 对运行过程做追踪、监控和性能优化。

组件角色一句话
LangChain积木提供模型、提示词、工具、链
LangGraph结构把积木搭成有循环、分支、状态的图
LangSmith观测看它跑得好不好：追踪、监控、评估
关系：LangChain 提供积木，LangGraph 负责搭结构，LangSmith 负责看它跑得好不好。
06

LangChain vs LangGraph

Chain vs Graph
维度LangChain · 线性链架构LangGraph · 动态图架构
核心结构线性、单向的执行流程，步骤之间顺序依赖非线性的有向图，用节点和边表达复杂逻辑关系
执行路径路径基本固定或仅有有限分支，复杂跳转比较吃力动态路由，天然支持循环、条件分支和多 Agent 协作
状态管理隐式管理，靠 Memory 模块在步骤间手动传递上下文全局共享的 State 对象，显式、统一地管理全流程状态
适用场景逻辑简单、步骤固定的短周期任务，上手门槛低长周期、复杂决策、多步骤任务，可追溯性和可控性强

怎么选

用链就够LangChain

  • 一次性问答、摘要、翻译、信息抽取
  • 步骤固定：提示词 → 模型 → 解析
  • 不需要回头、不需要暂停等人

请出图LangGraph

  • 需要循环：反思、重试、ReAct 多轮工具调用
  • 需要分支：按模型判断或业务规则路由
  • 需要持久化 / 人工介入：长任务、审批节点
两者不是替代关系，而是互补关系。简单任务用链就够了，没必要上图；需要循环、分支、持久化和人工介入时，再请出 LangGraph。

下节预告：动手搭建第一张图

preview.py
from langgraph.graph import StateGraph, MessagesState, START, END

builder = StateGraph(MessagesState)          # State：共享状态
builder.add_node("agent", call_model)        # 节点：做事
builder.add_node("tools", run_tools)
builder.add_edge(START, "agent")             # 基础边：固定直连
builder.add_conditional_edges("agent", should_continue, ["tools", END])  # 条件边：按规则分流
builder.add_edge("tools", "agent")           # 回到 agent，形成循环

graph = builder.compile()
